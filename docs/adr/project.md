
## ერთი წყარო
კალათა CartContext-შია (სერვერის პასუხი). ბეჯი და კალათის გვერდი ერთსა და იმავეს კითხულობს.
ჯამებს (lineTotal, subtotal) სერვერი ითვლის, ფრონტზე არ ვითვლით.

## სტეპერის სწრაფი დაჭერები
არჩეულია: სტეპერი ითიშება, სანამ მოთხოვნა მიმდინარეობს.
რატომ: პარალელური PATCH-ები შეიძლება არასწორი თანმიმდევრობით დაბრუნდეს.
გათიშვით ერთდროულად მხოლოდ ერთი მოთხოვნა არსებობს, ამიტომ ეკრანის რიცხვი ყოველთვის სერვერის პასუხია.
ტრადეოფი: ძალიან სწრაფი დაჭერისას რამდენიმე დაჭერა "იკარგება" (ღილაკი მცირე ხნით გათიშულია).
Debounce არ გამოვიყენეთ, რადგან რიცხვი ეკრანზე მაშინვე არ შეიცვლებოდა.

## ორი id
productId მხოლოდ POST /cart/items-ზე. item.id (პოზიციის id) PATCH/DELETE-ზე.

## გამოსვლა
unauthenticated სტატუსზე კალათა ფრონტზე ნულდება, სერვერზე რჩება.
