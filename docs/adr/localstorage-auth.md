# ADR 001: ტოკენის შესანახად localStorage-ის გამოყენება და პროფილის განახლების UX გადაწყვეტილებები

## სტატუსი
მიღებულია (Accepted)

## 1. ტოკენის შენახვა: localStorage vs httpOnly cookie
- **გადაწყვეტილება:** ვიყენებთ `localStorage`-ს.
- **მიზეზი:** სიმარტივე - `localStorage` მარტივია მუშაობისას და აადვილებს ტოკენის წაკითხვას, შენახვას და გასუფთავებას.
- **რისკები (XSS):** მოწყვლადია მავნე JavaScript კოდის მიმართ. პროექტში ვრწმუნდებით, რომ არ ვიყენებთ დაუცველ გარე პაკეტებს.

## 2. პროფილის რედაქტირება და „შენახვა“ ღილაკის ლოგიკა
- **isDirty შემოწმება:** „შენახვა“ ღილაკი გათიშულია (`disabled`), სანამ მომხმარებელი რეალურ ცვლილებას არ შეიტანს (`isDirty === false`). ეს გამორიცხავს ცარიელ მოთხოვნებს სერვერზე.
- **Loading / Spiner:** გაგზავნის მომენტში ირთვება სპინერი და იბლოკება ღილაკი, რათა გამოირიცხოს ორმაგი გაგზავნა (Double Submit).

## 3. მიმდინარე პაროლის ლოკაცია პროფილის გვერდზე
- **გადაწყვეტილება:** მიმდინარე პაროლის ველი განთავსებულია **უშუალოდ ფორმის ბოლოს** (და არა ცალკე მოდალში).
- **დასაბუთება:** ეს მიდგომა ამცირებს ინტერფეისის გადატვირთვას და მომხმარებელს საშუალებას აძლევს ერთიან, მარტივ ველში შეიყვანოს ახალი მონაცემები და თავისი ძველი პაროლი ცვლილებების დასადასტურებლად, რაც აჩქარებს პროცესს.
