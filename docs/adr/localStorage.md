# ADR 001: ტოკენის შესანახად localStorage-ის გამოყენება httpOnly cookie-ს ნაცვლად

## სტატუსი
მიღებულია (Accepted)

## კონტექსტი
აუთენთიფიკაციისთვის აუცილებელია კლიენტის მხარეს JWT ტოკენის შენახვა. განვიხილეთ ორი ძირითადი მიდგომა: `localStorage` და `httpOnly cookie`.

## რატომ localStorage და არა httpOnly cookie?
სიმარტივე - `localStorage` ჩემთვის ნაცნობია როგორც რეაქტის, ისე ჯავასკრიპტის ლექციებიდან. მასთან მუშაობა მარტივია, ასევე სინტაქსიც მემარტივება. ეს აადვილებს ტოკენის წაკითხვას, შენახვას და გასუფთავებას.

## რისკები და უსაფრთხოება (XSS)
მეორე მხრივ, `localStorage` მოწყვლადია კიბერშეტევების მიმართ. თუ აპლიკაციაში მავნე ჯავასკრიპტის კოდი მოხვდა, ჰაკერს შესაძლოა ტოკენზე ჰქონდეს წვდომა.
